## 工控机实际执行

Ubuntu 22.04 / ROS 2 Humble / Python 3.10，独立项目虚拟环境，原系统ROS及其他工作空间未变更。

- 清理后仅3个ROS包，已从源码编译通过（rslidar_sdk、rslidar_msg、camera_usb_pkg）。
- 完整静态检查、lint和26项回归测试通过，包括无红绿灯时保存14路、加入图像后恢复15路的回归。
- 独立ROS域193模拟未来红绿灯相机，保存4 PCD + 1 PNG；停止发布后的过期/缺席处理通过。
- 使用本项目新编译驱动，红绿灯专用页面缺席相机时保存四雷达；普通联合页面保存其余14路。均记录可选缺席，正常退出并恢复Pi图传模式。
- 实际内参采集入口读取GMSL1920×1080和鱼眼800×600并完成短录。现场无标定板，数据不足按原规则返回退出码2；没有将无板短录视作有效标定。红绿灯内参入口明确跳过。
- Pi187当前四颗UNIQUESKY相机经实时V4L2查询，MJPEG支持1920×1080/1280×720/800×600/640×480，当前保持800×600，不支持1600×1200。

## 模拟求解（不是实车精度）

用户明确授权没有实拍板数据时使用模拟。可用 `./scripts/validate_black_workflows.sh` 重现，输出目录为output/simulation_*，报告标记 `SYNTHETIC_SOFTWARE_VALIDATION_ONLY`、`hardware_calibration=false`。

- 内参：渲染已知参数的ChArUco图像，实际运行GMSL pinhole和800×600 fisheye求解。独立阶段验收的最大焦距相对误差分别约0.084%和0.117%；鱼眼原有覆盖、重投影和bootstrap质量门限通过。
- 联合外参：16组渲染AprilGrid图像、10颗模拟相机和独立生成的雷达观测。三颗相对雷达与十颗相机均求解成功；独立阶段验收最大位移误差约1.71 mm、最大旋转误差约0.103°。主雷达作为参考帧，不单独求解；红绿灯缺席在结果中明确记录。
- BEV：原生800×600合成地面纹理，执行图像检测入口；用明确标记的已知地面板观测验证绝对映射和原14组/三阶段协议的相对拼接，执行质量校验和最终渲染。全部自检通过，remap为512×512 float32、有限数值，所有有效采样坐标均在800×600源图内。此处地面板观测是解析模拟，不是从现场照片拟合。

上述数值只说明软件对模拟真值的恢复能力。没有实拍板数据，因此未声称得到黑车实车内外参，未将模拟结果写入config/black_vehicle/intrinsics或Autoware配置。

## 已修复的问题

1. GMSL通道/格式与USB默认设备不符：改用已读帧确认的0、3、4、5、6、7及UYVY/1920×1080。
2. 标定入口使用历史相机命名和雷达端口：由黑车profile驱动，保留原算法模块。
3. BEV若干位置写死1600×1200：读取CameraInfo/包内源尺寸；内外参不可跨分辨率套用。
4. 红绿灯相机缺席：保留第15槽及所有工作流，记录可选缺席，不等待或阻塞其余数据保存。
5. Humble重复关闭ROS导致退出异常：使用显式信号处理和有条件shutdown。
6. 外部旧雷达工作空间依赖：使用本项目编译驱动及黑车初始TF；GMSL纳入已确认card0 SDK快照，模块逐字节不变。

测试日志与实际采集仍保存在工控机 `~/black_vehicle_review/evidence/` 和项目 `output/hardware_acceptance/`，模拟图像/报告保存在 `~/black_vehicle_review/simulation/`。源代码、配置和可复现验证工具入Git，采集数据与模拟参数不入Git。
