## 1. 结论

任务 C 的 205 轮结果只能作为诊断候选，不能整体覆盖 Autoware。循环在第
205 轮停止，是因为连续 5 轮满足了第 200 轮后放宽的 bootstrap 重复性门限
（1 cm / 1 deg），并不代表所有传感器获得了相同等级的物理准确度。

按照本次政策——车辆和传感器机械位置没有改变，允许沿用此前已经通过静态
重复性验证的外参——可以把以下传感器的**上次可用外参原值**作为条件通过值：

- 三颗 BPearl：左前、右前、后；
- 四颗侧向普通 USB 相机：前左、前右、后左、后右；
- 左、右鱼眼相机（分辨率改变不等于机械外参改变）。

不能写入本轮新估计值的传感器：前中普通相机、后中普通相机、前鱼眼、后鱼眼。
交通灯相机属于任务 E，任务 C 没有把它纳入求解，亦不能由任务 C 部署。

“条件通过”表示可以保留上次静态外参作为当前工程值，但不能宣称本批数据完成了
独立跨日 1 cm / 1 deg 验证。当前多日求解把这些节点冻结为锚点，所谓跨日变换
差为 0 是算法约束的结果，不是第二次独立测量。

## 5. 部署规则

1. 本报告中的“条件可写入”只能复制上次可用 YAML 的完整矩阵/四元数，不使用
   `multiday_hierarchical_result.yaml` 对锚点重新生成数值。
2. 前中、后中、前鱼眼、后鱼眼继续保留在 `review_only`，不得进入活动 TF。
3. 普通 USB 六相机中，只有前左、前右、后左、后右具备可沿用的静态外参；
   前中和后中不能因为物理安装未动就把此前 `requires_recapture` 值升级为真值。
4. 交通灯相机由任务 E 单独验收；任务 C 不提供部署授权。
5. 真正写入前仍应做一次静态验收：主雷达与三颗 BPearl 的地面/墙柱重合、四颗
   侧向 USB 相机的点云投影方向、全部 TF 连通性。任何出现超过 10 cm 明显错位的
   传感器应立即回退到 `review_only`。
